## ขั้น 3 — ตรวจทานก่อน merge (Opus)

พบและแก้:
1. **ผู้สมัครชี้ "หน่วยงานที่ขอ" ไปที่เขตได้** — ผู้ที่ยังรออนุมัติแก้ `requested_org_id` ของตนเองผ่าน API ได้ ถ้าชี้ไปที่เขต (หรือโรงเรียนที่ปิด) แล้วได้รับอนุมัติ จะกลายเป็น "ครูของเขต" → เพิ่มสังกัดอัตโนมัติเฉพาะ**โรงเรียนที่เปิดอยู่** · pgTAP 2 ข้อ · mutation = **FAIL**
2. **หน้าเก่าวาดทับหน้าใหม่ (บั๊กเดิมตั้งแต่ Phase 3b ไม่ได้เกิดจาก 4f)** — `route()` รอนับตัวเลขในเมนูก่อนวาด ถ้าเปลี่ยนหน้า 2 ครั้งติดกันและหน้าแรกตอบช้า หน้าแรกจะวาดทับหน้าที่สอง (ที่อยู่เป็นหน้าหนึ่ง แต่จอแสดงอีกหน้า) · เป็นสาเหตุที่ `dialogs.spec.js` ตกเป็นครั้งคราวในชุดเต็ม 3 ครั้งระหว่าง 4f (ภาพตอนตกบน WebKit ค้างที่หน้ารายการหลักสูตร) → `createNavigationGuard()` ใน `core/router.js`: วาดเฉพาะการเปลี่ยนหน้าล่าสุด · unit 2 ข้อ · E2E ใหม่ `navigation-race.spec.js` หน่วงคำขอของหน้าแรกให้เกิดเหตุการณ์จริง · mutation (ถอด guard) = **FAIL** (หน้ารายการหลักสูตรวาดทับหน้าบทเรียน)
3. ข้อความหน้ารออนุมัติ/ถูกระงับยังอ้างถึงผู้บริหารสถานศึกษา → เปลี่ยนเป็นผู้ดูแลระบบหรือผู้ดูแลเขต
4. ตรวจแล้วรับได้: Staff อ่านอีเมลติดต่อ (`get_profile_contact`) ของบัญชีทั่วไปได้ — สอดคล้องกับที่เห็นอีเมลเข้าสู่ระบบในหน้าจัดการบัญชีอยู่แล้ว (บันทึกใน PERMISSIONS) · Staff ไม่มีช่องทางเพิ่มบทบาทโดยตรง (ผ่าน `admin_set_school` เท่านั้น) · `admin_delete_account` ยังเป็นของผู้ดูแลระบบเท่านั้น

เอกสาร: `DATA_DICTIONARY.md` (สร้างใหม่จากฐานข้อมูล), `PERMISSIONS.md`, `API_CONTRACTS.md`, `ARCHITECTURE.md`, `ERD.md`, `DEPLOY.md` (ขั้นขึ้น 4f), `PLAN_OBEC_SCALE.md`, `README.md` · `BLUEPRINT.md` ยังยกตัวอย่าง `school_admin` — ไม่ได้แก้ (เอกสารต้นทางของเจ้าของระบบ)

## ความเสี่ยงที่ยังเหลือ

- ยกเลิกบทบาทแล้วย้อนกลับยาก (check constraint) — ระบบจริงไม่มีผู้บริหารโรงเรียนอยู่แล้ว
- Staff ระงับศึกษานิเทศก์ได้ (ตามกติกา "ทุกคนยกเว้นผู้ดูแลเขตและผู้มีบทบาทระดับระบบ")
- ผู้ที่ถูกปฏิเสธ (pending → suspended) แล้วเปิดใช้ภายหลังจะไม่ได้สังกัดอัตโนมัติ (ไม่ใช่ pending → active) — กำหนดโรงเรียนได้จากหน้าจัดการบัญชี
- ผู้ใช้สาธิต 2 คนยังชื่อ "ผู้บริหาร โรงเรียนสาธิต ก/ข" (เป็นครูแล้ว) — มีผลเฉพาะฐานข้อมูล local
- เครื่องทดสอบเข้า sleep ระหว่างรันหลายครั้ง (`pmset -g log`) — รันด้วย `caffeinate -dims`
