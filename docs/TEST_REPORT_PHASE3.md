## ขั้น 8 — ตรวจทานก่อน merge (Opus) + ปิด Phase

**ตรวจ:** ทุกตาราง public ใหม่มี GRANT เฉพาะคอลัมน์ + RLS + pgTAP อนุญาต/ปฏิเสธ · ทุกฟังก์ชัน SECURITY DEFINER มี `search_path = ''`, ตรวจ `auth.uid()`, revoke จาก public/anon · เวลาที่เป็นหลักฐาน (`submitted_at`, `is_late`, `released_at`, `created_at` ของไฟล์) มาจาก server · ผู้เรียนเขียนผลตรวจ/สถานะ/เวลาไม่ได้ · ลิงก์ https เท่านั้น ทั้ง server (trigger) และหน้าเว็บ (`safeUrl`, `rel=noopener`) · ข้อความของผู้ใช้ทุกช่องแสดงผ่าน `html```/escape · CSV ไม่มีเนื้อหางานและกันสูตร (`toCsv`) · bucket ใหม่ส่วนตัว ไม่มี policy update (ไม่ทับไฟล์) ผู้ตรวจเปิดได้เฉพาะงานที่ส่งแล้ว

**พบและแก้ 1 จุด (race condition):** trigger ของไฟล์แนบตรวจ "ยังเป็นร่าง" และ "ไม่เกิน 5 ไฟล์" โดยไม่ล็อกแถวของรอบ → **ทดลองสองเซสชันจริง:** เซสชัน 1 เรียก `submit_task_submission` ค้าง transaction 3 วินาที เซสชัน 2 แนบไฟล์ระหว่างนั้น → ก่อนแก้: งานสถานะ "ส่งแล้ว" มีไฟล์ที่แนบหลังเริ่มส่ง 1 ไฟล์ (ขัดกติกา "ส่งแล้วแก้ไม่ได้") · หลังแก้ (trigger `SELECT … FOR UPDATE` แถวของรอบก่อนตรวจ): การแนบรอให้การส่งเสร็จแล้วถูกปฏิเสธ "files are added to a draft only" งานที่ส่งมีไฟล์ 0 · การล็อกเดียวกันกันการแนบพร้อมกันจนเกิน 5 ไฟล์ · migration นี้ยังไม่เคย merge/deploy จึงแก้ในไฟล์เดิม

## สรุป Phase 3

ภาระงาน + Rubric ครบวงจร: วิทยากรสร้าง Rubric (เกณฑ์ × ระดับ มีฉบับ) → สร้างภาระงาน เลือก Rubric เผยแพร่ เปิดให้รุ่นพร้อมกำหนดส่ง → ผู้เรียนส่งข้อความ ลิงก์ ไฟล์ (bucket ส่วนตัว) → วิทยากร/ครูพี่เลี้ยง (เฉพาะครูที่ดูแล) ตรวจด้วย Rubric ร่างเป็นส่วนตัว ส่งผล "ผ่าน/ส่งกลับแก้ไข" → ผู้เรียนเห็นคะแนนรายเกณฑ์และข้อเสนอแนะ ส่งรอบใหม่ได้ตามจำนวนรอบ → ตรวจใหม่ได้โดยต้องมีเหตุผล เก็บประวัติและ audit → CSV รายรุ่นไม่มีเนื้อหางาน · คะแนนทุกค่ารวมที่ server · ไม่รวม PNI (ตามที่เจ้าของตัด), portfolio, ผู้ตรวจสองคน, อีเมล, ลิงก์จากบทเรียน

- ข้อความ error ทั่วไปบางรหัส (SE001–SE003) ยังใช้ถ้อยคำของแบบทดสอบ — หน้าเว็บกันไว้ก่อนด้วยปุ่ม/สถานะ จึงพบยาก
- ไฟล์อยู่ใน Supabase Storage — สำเนาไป Google Drive ส่วนกลาง (ทางเลือก ข.) ทำเป็นงานแยกได้เมื่อเจ้าของอนุมัติกุญแจ
