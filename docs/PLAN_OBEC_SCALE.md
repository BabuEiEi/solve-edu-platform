# แผนต่อยอดสู่ระดับ สพฐ. — โปรเจกต์ใหม่

> สถานะ: แผน (ยังไม่เริ่มพัฒนา) · จัดทำ 2569-11-08
> ฐานปัจจุบัน: ระบบระดับเขต **สพม.พิษณุโลก อุตรดิตถ์** (โรงเรียน 57 แห่ง) — Supabase `hcudarobowuwsmmyoyrd` + Vercel `solve-edu-platform` (ดู `docs/DEPLOY.md`)
> หลักการ: **ใช้โค้ดชุดเดียวกัน แต่ติดตั้งเป็นโปรเจกต์ใหม่** (Supabase + Vercel ชุดใหม่) สำหรับระดับ สพฐ.

ทำไมแยกโปรเจกต์ (ไม่ขยายของเขต):
- ระบบของเขตใช้งานต่อได้ไม่สะดุด ทดลองระดับประเทศได้โดยไม่กระทบข้อมูลจริงของเขต
- แยกผู้ควบคุมข้อมูลส่วนบุคคล (PDPA), งบประมาณ, โดเมน, และผู้ดูแลระบบ ได้ชัดเจน
- ภายหลังถ้าต้องการรวม: ย้ายข้อมูลของเขตเข้าโปรเจกต์ สพฐ. ได้ (ส่งออก/นำเข้าตามรหัสหน่วยงานทางการ)

## 2. สิ่งที่ต้องตัดสินใจก่อนเริ่ม

- [ ] **เจ้าของระบบและผู้ควบคุมข้อมูล (PDPA)** — หน่วยงานใดเป็นผู้ควบคุมข้อมูล ใครเป็นผู้ดูแลระบบระดับ สพฐ.
- [ ] **โดเมน** — เช่น โดเมนย่อยของ สพฐ. (ต้องให้ผู้ดูแล DNS ของหน่วยงานตั้งค่า) หรือใช้ `*.vercel.app` ระหว่างนำร่อง
- [ ] **งบประมาณบริการ** — Supabase Pro, Vercel Pro, พื้นที่เก็บไฟล์ส่วนเกิน, SMTP (ตรวจราคาปัจจุบันก่อนเสนอ)
- [ ] **บัญชีบริการขององค์กร** — สร้างโปรเจกต์ Supabase/Vercel ในบัญชีของหน่วยงาน (ไม่ใช่บัญชีส่วนตัว) และกำหนดผู้มีสิทธิ์ ≥ 2 คน
- [ ] **รูปแบบการอบรม** — โครงการเดียวทั้งประเทศ แบ่งรุ่นตามเขต/ภูมิภาค หรือแต่ละเขตจัดเอง
- [ ] **ช่องทางช่วยเหลือผู้ใช้** — ใครตอบคำถามเรื่องสมัคร/ลืมรหัสผ่าน/อนุมัติ (helpdesk ระดับเขต)

## 3. ข้อมูลที่ต้องเตรียม

ไฟล์ทั้งหมดเป็น **CSV (UTF-8)** หรือ Excel ที่ส่งออกเป็น CSV ได้ · ใช้ **รหัสทางการ** เป็นตัวเชื่อมทุกไฟล์

### 3.1 หน่วยงาน (จำเป็น)

**ก. เขตพื้นที่ — 245 แถว**

| คอลัมน์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `area_code` | (รหัสเขตทางการของ สพฐ.) | ไม่ซ้ำ · ใช้ตลอดอายุระบบ |
| `name` | สำนักงานเขตพื้นที่การศึกษามัธยมศึกษาพิษณุโลก อุตรดิตถ์ | ชื่อเต็ม |
| `short_name` | สพม.พิษณุโลก อุตรดิตถ์ | ชื่อย่อที่ใช้แสดง |
| `area_type` | สพม. / สพป. | |
| `province` | พิษณุโลก, อุตรดิตถ์ | ไม่บังคับ (ใช้กรอง/รายงาน) |

**ข. โรงเรียน — ราว 2.9 หมื่นแถว**

| คอลัมน์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `school_code` | 1065012002 | รหัสสถานศึกษา 10 หลัก · ไม่ซ้ำ |
| `name` | โรงเรียนเฉลิมขวัญสตรี | ชื่อเต็มพร้อมคำว่า "โรงเรียน" |
| `area_code` | (รหัสเขตเดียวกับไฟล์ ก.) | ต้องมีอยู่ในไฟล์ ก. |
| `province`, `district` | พิษณุโลก, เมืองพิษณุโลก | ไม่บังคับ (ช่วยค้นหาตอนสมัคร) |
| `status` | เปิด / ยุบรวม | โรงเรียนที่ยุบรวมจะถูกปิดใช้ ไม่ลบ (ประวัติยังอยู่) |

แหล่งข้อมูลที่แนะนำ: ศูนย์เทคโนโลยีสารสนเทศของ สพฐ. หรือชุดข้อมูลสถานศึกษาบน data.go.th — ขอฉบับล่าสุดพร้อมวันที่ของข้อมูล
ข้อมูลระดับเขตปัจจุบันใช้รหัสโรงเรียนทางการอยู่แล้ว จึงจับคู่กับไฟล์ระดับประเทศได้ (รหัสเขต `สพม.พิษณุโลก อุตรดิตถ์` จะถูกเปลี่ยนเป็นรหัสทางการตอนนำเข้า)

### 3.2 ผู้ดูแล (จำเป็น)

| ไฟล์ | คอลัมน์ | จำนวนโดยประมาณ |
|---|---|---|
| ผู้ดูแลระดับ สพฐ. | `email`, `full_name` | 2–5 คน |
| ผู้ดูแลเขต (`district_admin`) | `email`, `full_name`, `area_code` | 1–2 คน/เขต → 245–490 คน |
| ศึกษานิเทศก์ (`supervisor`) | `email`, `full_name`, `area_code` | ตามจริง |
| ผู้ดูแลโรงเรียน (`school_admin`) | `email`, `full_name`, `school_code` | ไม่บังคับ |

อีเมลต้องเป็นอีเมลที่เจ้าตัวใช้สมัครจริง (แนะนำอีเมลของหน่วยงาน) · ระบบจะให้สิทธิ์อัตโนมัติเมื่อเจ้าของอีเมลสมัคร ไม่ต้องอนุมัติทีละคน

### 3.3 การอบรม (ต่อโครงการ)

- **โครงการ**: ชื่อ, หน่วยงานเจ้าของ (สพฐ. หรือเขต), ช่วงเวลา
- **หลักสูตร**: หน่วยการเรียน บทเรียน เนื้อหา วิดีโอ (ลิงก์ YouTube/Vimeo) แบบทดสอบ (นำเข้า CSV ได้แล้ว) Rubric และภาระงาน
- **รุ่น**: รหัส/ชื่อรุ่น (เช่น รายเขตหรือรายภูมิภาค), วันเริ่ม–สิ้นสุด
- **รายชื่อต่อรุ่น**: `email`, `full_name`, `school_code`, `cohort_code`, `role` (`trainee` / `trainer` / `mentor` / `coordinator`) และคู่ครูพี่เลี้ยง–ผู้เรียน (ถ้ามี)

### 3.4 เอกสารประกอบ

- ประกาศความเป็นส่วนตัว (PDPA) และข้อตกลงการใช้งาน — แสดงตอนสมัคร
- ระยะเวลาเก็บข้อมูลและไฟล์งาน (ระบบล้างไฟล์ค้างอัตโนมัติอยู่แล้ว แต่ไฟล์งานที่ส่งเก็บตลอด)
- คู่มือสั้นสำหรับ: ผู้ดูแลเขต (อนุมัติ/นำเข้ารายชื่อ), วิทยากร (ตรวจงาน), ผู้เรียน (สมัคร/ส่งงาน)

## 5. ติดตั้งโปรเจกต์ใหม่ (ทำซ้ำตาม `docs/DEPLOY.md` และ `docs/DEPLOY_PHASE3B.md`)

ทุกข้อที่แตะบริการจริงต้องได้รับอนุมัติจากเจ้าของระบบ

1. Supabase: สร้างโปรเจกต์ใหม่ในบัญชีองค์กร · **Region Singapore** · แผน Pro · ตั้งรหัสผ่านฐานข้อมูลเก็บไว้เอง
2. `npx supabase link --project-ref <ref ใหม่>` (เจ้าของระบบรัน) → `db push --dry-run` → อนุมัติ → `db push` (ไม่ใส่ข้อมูลสาธิต)
3. ตรวจความปลอดภัยบนโปรเจกต์ (RLS ทุกตาราง, สิทธิ์ฟังก์ชัน, security advisor) ด้วยชุดเดียวกับที่ใช้กับโปรเจกต์ของเขต
4. ติดตั้ง Edge Functions + `CRON_SECRET` + ตั้งเวลาล้างไฟล์ · (Google Drive เมื่อพร้อมและยืนยัน PDPA)
5. Vercel: โปรเจกต์ใหม่ในทีมขององค์กร · ตั้งค่า `VITE_SUPABASE_*` · deploy **preview ก่อน** (`--target=preview`) · ผูกโดเมน
6. Supabase Auth: Site URL / Redirect URLs ตามโดเมน · **SMTP ขององค์กร (จำเป็น)** · Google login (ถ้าใช้)
7. ผู้ดูแลระบบคนแรก (SQL ใน `docs/DEPLOY.md`)
8. นำเข้าหน่วยงาน (ข้อ 3.1) → นำเข้าผู้ดูแลเขต (ข้อ 3.2) → ตรวจว่าแต่ละเขตเห็นเฉพาะของตน
9. ขึ้น production เมื่อผ่านนำร่อง

## 7. ประมาณการทรัพยากร (คำนวณใหม่เมื่อรู้จำนวนจริง)

- **ผู้ใช้**: จำนวนครูที่อบรม + วิทยากร + ผู้ดูแล → ตรวจกับโควตาผู้ใช้ต่อเดือนของแผน Supabase
- **พื้นที่ไฟล์**: ผู้เรียน × ภาระงาน × จำนวนไฟล์ × ขนาดเฉลี่ย — ตัวอย่าง 30,000 คน × 2 ภาระงาน × 2 ไฟล์ × 2 MB ≈ 240 GB
- **อีเมล**: สมัคร + ยืนยัน + ลืมรหัสผ่าน ≈ 2–3 ฉบับต่อคน → ต้องใช้ SMTP ขององค์กรหรือบริการส่งอีเมล
- **ช่วงใช้งานพร้อมกัน**: วันเปิดรุ่น/วันกำหนดส่งงาน — ทดสอบโหลดตามสถานการณ์นี้ (ขั้น 6)

## 8. ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| ข้อมูลโรงเรียนไม่ล่าสุด (ยุบรวม/เปลี่ยนชื่อ) | ครูหาโรงเรียนไม่เจอ | นำเข้าซ้ำได้ตามรหัส · ปิดใช้แทนลบ · ช่องแจ้ง "ไม่พบโรงเรียน" |
| ผู้ดูแลเขตไม่อนุมัติ | ผู้สมัครค้าง | นำเข้ารายชื่อล่วงหน้า (ได้สิทธิ์ทันที) · รายงานคำขอค้างต่อเขต |
| อีเมลไม่ถึงผู้ใช้ | สมัคร/ลืมรหัสผ่านไม่ได้ | SMTP ขององค์กร + ตั้ง SPF/DKIM ของโดเมน |
| ต้นทุนพื้นที่ไฟล์สูง | งบเกิน | จำกัดขนาด/จำนวนไฟล์ต่อภาระงาน (มีอยู่แล้ว) · ส่งสำเนาไป Google Drive ขององค์กร (มีอยู่แล้ว) |
| ใช้บัญชีส่วนตัวเป็นเจ้าของบริการ | เสี่ยงเข้าไม่ได้เมื่อคนเปลี่ยน | สร้างทุกบริการในบัญชีองค์กร มีผู้ดูแล ≥ 2 คน |

## 9. ลำดับงานที่แนะนำ

1. ใช้ระบบระดับเขตจริงก่อน (ระยะ 0) และเก็บข้อเสนอแนะ
2. ระหว่างนั้นเตรียมข้อมูลข้อ 3.1–3.2 และตัดสินใจข้อ 2
3. พัฒนาขั้น 1–4 (พอสำหรับนำร่อง) → ติดตั้งโปรเจกต์ใหม่ (ข้อ 5) → นำร่องระยะ 1
4. พัฒนาขั้น 5–8 ระหว่างนำร่อง → ขยายระยะ 2–3
