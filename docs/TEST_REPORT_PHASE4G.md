## ขั้น 5 — ตรวจทานก่อน merge (Opus)

พบและแก้:
1. **ช่องว่างของขั้น 4** — migration `20261110090100_my_cohort_courses.sql`: `my_cohort_courses()` รุ่นที่ตนเป็นผู้เข้าอบรม (รวมรุ่นที่ปิดรับสมัคร ไม่รวมที่เก็บถาวร) + หลักสูตรที่เผยแพร่ + การลงทะเบียนของตนเอง (ไม่มีข้อมูลคนอื่น) · `#/join` มีส่วน "รุ่นของฉัน" แยกจาก "เปิดรับสมัครอยู่ตอนนี้" (ไม่แสดงซ้ำ)
2. **ลงทะเบียนเองในรุ่นที่จบแล้ว/เก็บถาวรได้** — `enroll_in_course` ไม่ตรวจสถานะรุ่น → ลงทะเบียนเองได้เฉพาะรุ่นเปิดรับ/กำลังอบรมในโครงการที่ดำเนินการ (SE014) · ผู้จัดการ/Staff ยังลงให้ได้ทุกเมื่อ · หน้าแสดง "รุ่นนี้ปิดแล้ว — ติดต่อผู้จัดการรุ่น"
3. **กดลงทะเบียนซ้ำพร้อมกันชน unique key** → `on conflict do nothing` แล้วใช้รายการเดิม
4. ตรวจเพิ่ม: ผู้รออนุมัติแก้สถานะตนเองเป็น active ผ่าน REST ไม่ได้ (RLS) · เทสต์ใหม่
5. **Integration ที่ชนกันซ้ำๆ (มีมาตั้งแต่ Course Builder)** — `builder.test.js` เผยแพร่ "บทเรียนร่าง" ของข้อมูลสาธิตชั่วครู่ ไฟล์อื่นที่รันพร้อมกันเห็นบทเรียนเพิ่ม (`rest-rls` เห็น 4 บทแทน 3, `storage` ลงนามไฟล์ได้) · ใน 4c แก้ด้วยการคืนสถานะ แต่ยังมีช่วงเวลาชน → เทสต์นี้สร้างหลักสูตร หน่วย บทเรียน และการลงทะเบียน (ครู ข1) ของตัวเอง ไม่แตะสิ่งที่ไฟล์อื่นอ่านอีก

ตรวจแล้วรับได้ / เป็นข้อจำกัดที่ทราบ:
- ผู้จัดการเพิ่มคนเกินที่นั่งได้ (ที่นั่งคุมเฉพาะการสมัครเอง/อนุมัติคำขอ) — ตั้งใจให้ผู้จัดการมีอำนาจเหนือการตั้งค่า
- ผู้ประสานงานรุ่นค้นหาคนได้เฉพาะคนที่ตนเห็นโปรไฟล์ (RLS) จึงเพิ่มคนใหม่จากนอกรุ่นได้จำกัด — ผู้จัดการโครงการ/Staff เพิ่มแทน
- Staff เพิ่มคนเป็น "วิทยากร" ได้ (วิทยากรตรวจงานและแก้หลักสูตรของรุ่นได้) — ตามที่ตกลงว่า Staff จัดการสมาชิกรุ่น
- นำหลักสูตรออกจากโครงการได้แม้มีผู้ลงทะเบียน (คนเดิมเรียนต่อได้ หน้าจอเตือนก่อน)
