## ขั้น 4 — ตรวจทานก่อน merge (Opus)

พบและแก้:
1. **ข้อความแจ้งเตือนของ `validate` ถูกใส่เป็น HTML** — `showValidationMessage` ของ SweetAlert2 ใช้ `setInnerHtml` · ตอนนี้ข้อความเป็นค่าคงที่ (ยังไม่มีช่องโหว่) แต่ถ้าวันหน้าข้อความยกสิ่งที่ผู้ใช้พิมพ์จะเป็น XSS → ตัวกลาง escape ข้อความเอง · unit test ใช้ข้อความที่มี `<img onerror>` · mutation (ถอด escape) = **FAIL**
2. **กล่องค้างเมื่อหน้าเปลี่ยน** — `window.confirm` บล็อกทั้งหน้า แต่กล่องใหม่ไม่บล็อก ถ้าเปิด "ลบ?" แล้วกด Back กล่องยังอยู่บนหน้าใหม่ และกด "ลบ" จะลบของจากหน้าเดิม → ปิดกล่องเป็น "ยกเลิก" เมื่อ `hashchange` (ใช้ `Swal.getPopup()` ไม่ใช่ `isVisible()` ซึ่งวัด layout และใน jsdom เป็นเท็จเสมอ) · unit + E2E (`page.goBack()` บนเบราว์เซอร์จริง) · mutation ทั้ง unit และ E2E = **FAIL**
3. **ลิงก์ใน editor ได้คำตอบช้าลง (async)** — เพิ่ม E2E: พิมพ์ เลือกข้อความ ใส่ลิงก์ผ่านกล่อง → ลิงก์อยู่บนข้อความที่เลือกจริง (ผ่านทั้งสองเบราว์เซอร์ ไม่ต้องแก้โค้ด)
4. **Integration ไม่นิ่ง (มีมาตั้งแต่ Course Builder ไม่ได้เกิดจาก 4c)** — `storage.test.js` "draft lesson media cannot be signed for a trainee" ตก 1 ใน 2 รอบ · สาเหตุ: `builder.test.js` เผยแพร่บทเรียนร่างแล้วไม่คืน และ vitest รันไฟล์ขนานกันบนฐานข้อมูลเดียว — **ไม่ใช่ช่องโหว่**: บทเรียนนั้นเผยแพร่แล้วจริงในจังหวะนั้น ผู้เรียนจึงได้สิทธิ์ตาม policy · แก้: เทสต์คืนสถานะร่างใน `finally` · ลองรันไฟล์ทีละไฟล์ (`--no-file-parallelism`) แล้วเจอเทสต์อื่นที่พึ่งลำดับไฟล์ (`assessment`, `assignments`) จึงไม่ใช้วิธีนั้น · หลังแก้รัน 5 รอบ ผ่าน 5/5

5. **E2E ของกล่องเองไม่นิ่งในชุดเต็ม** — รอบแรกในชุดเต็มตก (รันเดี่ยวผ่าน): `page.goBack()`/`goForward()` พาไปหน้าแรกแทนหน้าบทเรียน เพราะประวัติของเบราว์เซอร์ในชุดเต็มไม่แน่นอน และเทสต์ที่ค้างกลางทางทิ้งบล็อกวิดีโอไว้ ทำให้ `learning-flow` ตกตาม → เปลี่ยนหน้าด้วย `location.hash` (ยิง `hashchange` เหมือนปุ่ม Back) และย้ายเทสต์ไปบทเรียนร่าง (ไม่มีสเปกอื่นอ่าน) · อีกรอบหนึ่งตกเพราะผมรัน build/`npm audit` ซ้อนระหว่าง E2E จนหมดเวลา 30 วินาที — ไม่นับเป็นผล รันใหม่โดยไม่มีงานซ้อน
