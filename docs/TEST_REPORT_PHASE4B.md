ตรวจกับโปรแกรมจริง:
- **openpyxl (ตัวอ่านอิสระ)** โหลดไฟล์ที่เราเขียน 3 ไฟล์ (ผลส่งออก, แม่แบบรายชื่อ, แม่แบบข้อสอบ) ผ่านทุกข้อ: ชื่อชีตไทย · หัวตัวหนา · ตรึงแถวแรก · ตัวเลขเป็นตัวเลข · ค่าจริง/เท็จ · ข้อความที่หน้าตาเหมือนสูตร (`=1+1`, `@SUM(1)`) เป็นข้อความ · ขึ้นบรรทัดใหม่คงอยู่ · ช่องว่างเป็นช่องว่าง · ความกว้างคอลัมน์ ≤ 60 · คอลัมน์ `user_code` มีรูปแบบ Text
- **Microsoft Excel (Mac) จริง** เปิดไฟล์ผลส่งออกของเราผ่าน AppleScript ได้โดยไม่มีข้อความซ่อมไฟล์: ชื่อชีต "ผลสอบ" · หัวตารางถูก · `12.5` เป็นตัวเลข · `=1+1` แสดงเป็นข้อความ (ไม่ถูกคำนวณเป็น 2) · ชื่อที่มี `"` `<` `&` ถูกต้อง
- **ยังไม่ได้ทดสอบ: ไฟล์ที่ Excel เป็นผู้บันทึกเอง** — macOS ไม่ให้ Excel เขียนไฟล์ลงโฟลเดอร์ชั่วคราวของเครื่องมือ (การบันทึกไม่สำเร็จเงียบๆ) ความเข้ากันได้กับไฟล์ที่ Excel เขียนเองจึงยืนยันด้วยไฟล์จาก openpyxl และไฟล์ที่เลียนโครงสร้างของ Excel ในเทสต์ (shared strings, rich text, prefix namespace, attribute ของ Excel) เท่านั้น

อ่านทวน (ตัวอ่านไฟล์ที่ผู้ใช้อัปโหลด):
- ขนาดถูกตรวจ 3 ชั้น: ไฟล์ (5 MB) → ขนาดที่ประกาศของแต่ละส่วนและรวม ก่อนแตกไฟล์ → จำนวนแถว/คอลัมน์ · fflate แตกลงบัฟเฟอร์ที่มีขนาดเท่าที่ประกาศพอดี จึงประกาศเล็กแล้วข้อมูลจริงใหญ่ไม่ทำให้หน่วยความจำบวม (มี test)
- ไม่มี DTD: ข้อความ `<!DOCTYPE`/`<!ENTITY` ถูกปฏิเสธก่อนส่งให้ตัวแยก XML
- เลือกเฉพาะส่วนที่ต้องการ (`workbook`, `rels`, `sharedStrings`, `worksheets/*.xml`) ชื่อส่วนอื่นถูกข้าม · ไม่มีการเขียนไฟล์ลงดิสก์ จึงไม่มีช่องโหว่ zip-slip
- ข้อความจากไฟล์ผ่าน `html```` (escape อัตโนมัติ) เหมือน CSV เดิม · ตอนส่งออก ข้อความเก็บเป็นข้อความ จึงไม่ถูกรันเป็นสูตรใน Excel (CSV ยังมีตัวกัน `'` นำหน้าเหมือนเดิม)
- ไม่พบจุดที่ต้องแก้ในขั้นตรวจทาน · หมายเหตุ: ขั้นนี้ทำใน session ที่ใช้โมเดล Sonnet (ไม่ได้สลับเป็น Opus ตามแนวทางโครงการสำหรับรีวิวก่อน merge) — ถ้าต้องการให้ Opus ทวนส่วนอ่านไฟล์ (`xlsx.js`) อีกรอบก่อน merge ทำได้

ความเสี่ยงที่ยังเหลือ:
- ตัวแยก XML ของเบราว์เซอร์สร้างต้นไม้ทั้งชีตก่อนนับแถว ไฟล์ที่ใกล้เพดาน (ชีต 20 MB) อาจทำให้แท็บค้างครู่หนึ่ง — ไม่ใช่ช่องโหว่ (มีเพดาน) และไฟล์รายชื่อ/ข้อสอบจริงเล็กกว่ามาก
- ตัวเลขทศนิยมยาวที่ Excel เก็บเป็นค่ายาว (เช่น 0.30000000000000004) จะอ่านตามที่ Excel เก็บ · ไม่กระทบไฟล์ตัวอย่างและค่าปกติ (1, 0.5, 75)
- ถ้า Excel บันทึกรหัสที่เป็นตัวเลขล้วนในคอลัมน์รูปแบบตัวเลข เลข 0 นำหน้าจะหาย — เจ้าของระบบยืนยันว่ารหัสประจำตัวขึ้นต้นด้วยตัวอักษร จึงไม่กระทบ
- ช่องวันที่ใน Excel ถูกอ่านเป็นตัวเลขลำดับวันที่ — ไฟล์นำเข้าทั้งสองแบบไม่มีคอลัมน์วันที่
- รุ่น .xls เดิม (Excel 97–2003) ไม่รองรับ — ระบบแจ้งให้บันทึกเป็น .xlsx หรือ .csv
